# 朋友圈 · 界面发布（RPA）

把一段写好的纯文字发到微信朋友圈，**通过真实界面操作**完成：长按朋友圈右上角相机图标 → 打开纯文字编辑框 → 粘贴正文 → 回读校验 → 点「发表」。

不注入微信进程、不加载 DLL、不改内存。这是被「注入方案让客户端自己退出」教育出来的设计：界面操作最坏的后果只是这一次没点中，不会弄崩微信。

- 产物目录：`plugins/moments-rpa/`
- 插件 ID：`moments-rpa`
- 需要账号：否
- 权限：`storage`

## 前置条件

1. 电脑端微信已登录（实测 4.1.10.27）；
2. 电脑已解锁，微信没被最小化；
3. 发布时别抢鼠标——RPA 用的是真实光标。

不在朋友圈页面也没关系：第一次长按没出编辑框，插件会自动点「发现 → 朋友圈」再试一次。

## 工具（8 秒内）

| 工具 | 说明 |
| --- | --- |
| `status` | 今天发了几条、最近一条、工具是否就绪 |
| `check` | 只读检查：微信窗口在不在、是否停在朋友圈页、工具是否齐全 |
| `publish-text` | 发一条给定正文（需 `confirm=true`；`force=true` 可无视当天上限） |

## 动作（35 秒预算）

| 动作 | 说明 |
| --- | --- |
| `publish-text` | 发给定正文，会等编辑窗口关闭再回报 |
| `retry-last` | 重发最近一条（失败重试用） |

## 设置

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `holdMs` | 900 | 长按相机图标的毫秒数；低于 600 会被当成单击弹出「选择文件」 |
| `verify` | true | 发表前回读编辑框内容，与正文逐字比对，不一致就取消不发表 |
| `dryRun` | false | 演练模式：填字 + 校验后点「取消」，不真正发表 |
| `maxPostsPerDay` | 3 | 每日条数上限 |
| `ignoreDailyLimit` | false | 调试用，忽略上限 |

## 判断「真的发出去了」的依据

1. 编辑窗出现（`Qt51514QWindowIcon` + 标题「朋友圈」，约 410×450）；
2. 粘贴后剪贴板回读与正文一致（先放哨兵，`Ctrl+A`/`Ctrl+C` 再读回，避免「空编辑框也当成功」）；
3. 点「发表」后编辑窗句柄消失。

三条都满足才记 `accepted`。校验不过就取消、不发——宁可这次没发，也不发一条空动态。

## 命令行

```bash
node plugins/moments-rpa/tools/check.mjs
node plugins/moments-rpa/tools/send.mjs "今天风很大"
node plugins/moments-rpa/tools/send.mjs "测试" --dry
```

## 打包与安装

- 发行包：`dist/moments-rpa-1.0.0.zip`（275 KB，15 个文件，含 `bin/` 预编译工具与 `src/` 源码）
- ZIP 根目录直接是 `plugin.json` 与 `index.mjs`，符合安装器要求
- 重新打包：`node scripts/pack-plugin.mjs plugins/moments-rpa dist/moments-rpa-1.0.0.zip`
- 安装：应用「插件管理 → 从 ZIP 安装」；从 ZIP 装进来的插件默认是禁用状态，装完要在列表里启用

## 与 moments-native 的关系

`moments-native` 是「写稿 + 原生注入 / 网关 / 界面」的一体插件，带每日定时；本插件只做一件事：把给定正文安全发出去，不写稿、不定时，因此不会和它抢着发。两者可以同时启用。

## 已知限制

- 需要电脑保持解锁、微信在前台；
- 同一时刻只能发一条（没有并发保护）；
- 微信改版挪动了相机或按钮位置时，需要调整 `lib/rpa.mjs` 里的 `DEFAULT_GEOMETRY`（相对窗口的偏移量，不是屏幕绝对坐标）；
- 「编辑窗关闭」只是界面层证据，服务端是否收下仍以手机上的朋友圈为准。

详细方案、实测时间线与坐标表见 `plugins/moments-rpa/docs/方案说明.md`。
